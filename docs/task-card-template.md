# 小任务卡模板

适用于 `docs/implementation-plan.md` 的每一个独立编号。一张卡只交付一个行为；同阶段相邻编号也要分卡。主设计者先填完不可推断的输入、契约和验收预期，再交实现模型。缺少字段/有效期/协议/分支依据的卡保持 blocked。

## 空白卡

| 字段 | 主设计者必须填写的内容 |
| --- | --- |
| 任务编号与状态 | 原计划编号、子卡后缀（如确需拆分）、`ready / blocked / in-progress / tested`；关联台账行。 |
| 唯一目标 | 一句话说明一个函数行为、一个记录族、一个数据库操作、一个接口或一个界面行为。 |
| 用户可见结果 | 一个具体触发条件，以及完成后可观察的结果；避免“优化”“完善”等无边界描述。 |
| 前置条件 | 已完成任务编号、已存在契约、必需官方证据与当前基线提交；任何 blocked 前置不得略过。 |
| 允许修改 | 通常 1–3 个实现文件及对应测试的精确路径；不要把整个目录当作修改范围。 |
| 固定输入 | 文件路径/哈希、明确 synthetic 或真实来源、字段表/规范版本、一个最小正常输入和一个异常输入。 |
| 固定输出 | 已有类型或接口、字段名、精确示例结果、错误状态/错误码；不需要实现者发明新 schema。 |
| 保持规则 | 本卡相关的关键约束，例如原件不变、未支持腿必须断开、API 必须携带 release_id。 |
| 实现步骤 | 3–5 个顺序动作；每步对应一个可检查结果。若一步里有多个无关“并且”，继续拆卡。 |
| 验收断言 | 正常、关键异常和回归的具体预期；说明纯函数/合成资料/真实资料分别证明什么。 |
| 验收命令 | 在仓库根目录可直接执行的命令和预期退出状态；必要时注明本机环境变量及固定时钟。 |
| 停止条件 | 缺依据、样本冲突、契约不足、需扩范围、两轮修复失败；准确指出交回主设计者的问题。 |
| 交付要求 | 修改文件、测试真实结果、已知限制、独立提交 ID、台账状态；不得写没有执行过的验证。 |

### 执行规则

1. 读取本卡、约定文件与相应证据；核对前置条件后开始。先观察现有实现，不创建第二套相同接口。
2. 实现前确认测试预期已冻结。不能通过改预期、删除断言、吞掉异常或把未知字段设为允许来让测试通过。
3. 只完成卡内目标。修改范围超出 3 个实现文件、需要新 public 类型、改变权限或几何支持范围时，记录缺口交回拆卡。
4. 执行卡内测试。连续两轮仍失败，保留失败命令、输出和最小复现，交主设计者检查任务契约。
5. 成功后仅提交本卡文件；不把共享工作区中其他人的变更纳入，也不为回退本卡而重置整个工作区。
6. 报告明确区分 implemented、tested、partial 和 blocked。阶段末由主任务运行集成验收；卡内单元测试不能代替真实产品验收。

### 阻断记录格式

```text
任务：C07a
状态：blocked
已经确认：NASR EFF_DATE=2026/09/03，产品声明28天周期。
仍缺少：NASR产品明确的UTC起止时刻及其官方引用。
已保存证据：原件SHA、官方URL、README/字段文档的具体原文。
已经完成：获取、完整性校验、19,411条机场解析报告。
没有完成：创建精确有效期发布、Current提升、真实机场地图验收。
恢复条件：主设计者补充可核实的NASR时刻依据并冻结有效期读取规则。
```

这份阻断记录不能被改写成“默认使用 09:01Z”。用户曾批准实施计划，并不等于资料中缺失的事实已经存在。

## 已完成任务示例：D03 的单一异常输入检查

此例展示可直接交给低能力实现模型的任务粒度，已有实现与测试，不要求再次修改。

| 字段 | 冻结内容 |
| --- | --- |
| 唯一目标 | NASR APT_BASE 的非有限坐标必须计入错误，并保留对应原始字段。 |
| 前置条件 | A03 的 `APT DATA LAYOUT.pdf`/CSV structure 字段依据；D01 CSV reader 与 D02 `ResearchRecord` 已存在。 |
| 允许修改 | `services/ingestion/src/flightmap_ingestion/nasr.py`；`tests/test_parsers_faa.py`。 |
| 固定输入 | `tests/fixtures/nasr_synthetic.csv`，仅 synthetic。正常首行 LAT_DECIMAL=31.5、LONG_DECIMAL=-85.25；异常用例只把首行纬度改为 `nan`。SHA 在测试中使用 64 个 `a`，不得作为真实资产标识展示。 |
| 固定输出 | 正常：2 成功、0 错误；异常：input_count=2、success_count=1、unsupported_count=0、error_count=1，report.blocking=True。错误 code=`nasr-invalid-record`，severity=`error`，context.raw_fields 保留异常原值。 |
| 保持规则 | 原始文件不改写；ICAO 为空仍为空；第二条正常机场不被丢弃；不生成 nan GeoJSON。 |
| 实现步骤 | 读取字段；转换数字；检查 finite 和坐标范围；失败只记录本条错误；生成计数平衡的 ParseResult。 |
| 验收断言 | 异常不抛成整包静默失败；总数=成功+不支持+错误；不存在带非有限数值的 geometry。 |
| 验收命令 | `uv run pytest tests/test_parsers_faa.py -k nasr`，退出 0；`uv run ruff check services/ingestion/src/flightmap_ingestion/nasr.py tests/test_parsers_faa.py`，退出 0。 |
| 停止条件 | 如官方字段不是已有 LAT_DECIMAL/LONG_DECIMAL、需要改 Record 契约、或既有坐标预期与官方依据冲突，停止并提交差异说明。 |
| 交付 | 只提交上述两个文件的本卡变更，报告命令输出；只更新 D03 对应范围，不把 D04/D10 的真实发布/地图阻断一起标完成。 |

## 真实数据卡的附加要求

- 输入列出原件哈希、官方 URL、获取时间、ZIP 成员和记录位置；不要把真实大包复制到 tests/fixtures。
- 时间依据必须属于该产品，且精确有效期来自官方证据；日历函数只核对周期标签。
- CIFP 真实卡先确认用户处理协议以及合法获得的标准与样本。记录语法可以读取，不代表程序分支、引用和几何已有依据。
- `promote` 是独立明确动作。获取或构建测试只检查候选，不隐式提升；需要生命周期验收时先准备可审查报告，再由主任务执行已授权的显式提升。
- CIFP 几何卡必须附真实 IF/TF 前后原始腿、分支、唯一引用与独立预期；未知腿前后不得补线，合成用例通过不能作为真实 SID/STAR/进近验收。
