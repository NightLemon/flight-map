## 下一阶段建议：NASR 跑道日期级研究

原计划把跑道列在 CIFP 链路下。现有、已登记的 NASR APT ZIP 实际还包含 `APT_RWY.csv` 与 `APT_RWY_END.csv`，可以先开展独立来源的跑道研究，不必让全部新功能等待 CIFP。

本轮只读清点同一 SHA 原件：`APT_RWY.csv` 有 **23,174** 行，`APT_RWY_END.csv` 有 **39,816** 行。JFK `SITE_NO=15793.`、`SITE_TYPE_CODE=A` 的 `04L/22R` 及 `04L` 端记录存在；端记录同时提供跑道端坐标和 displaced threshold 坐标。这些是文件清点事实，**不是可发布跑道数量或已完成的字段语义验收**。

建议按下列顺序推进，各步产物经检查后再进入下一步：

1. **N01 官方字段依据与真实样本。** 核对包内 APT layout、结构 CSV 和 README；固定跑道/跑道端唯一键、父机场关系、单位、坐标基准、缺值与特殊设施规则。分别选取普通双端、位移入口、缺坐标和非普通跑道样本。端点与入口位置不能混用。
2. **N02 冻结新研究契约。** 当前 `research-1` 及存储校验明确仅允许机场 Point。先设计新 schema/解析器版本、记录类型与 capability、原件身份和兼容策略；不得原地改变已发布的旧快照含义。确定无需迁移还是新增迁移后，再编写实施卡。
3. **N03 解析与报告。** 从明确的官方键构建机场→跑道→跑道端关系；保留原字段/成员/行号；分别统计成功、不支持与错误；缺端点不猜长度或方向补线。新候选不自动激活。
4. **N04 API 与界面。** 版本固定的范围查询、机场资料中的跑道列表和地图图层；坐标端点与位移入口分别标注。继续使用同日期 d-TPP 机场图人工对照。
5. **N05 真实验收。** 至少 SEA/JFK 及异常样本；核对实际图形、端点、来源与目录；补新旧快照、撤销、恢复及范围查询回归。只有实际验证的范围才记 tested。

这条路线增加独立的 NASR 跑道研究能力，不解除 CIFP 程序语义阻断，也不把研究日期改写为精确有效时刻。
