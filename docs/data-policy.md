# 数据治理与发布规则

## 不虚构

- 不手工补写航路点、航段或程序腿。
- 不把同名五字码跨 FIR 自动合并。
- 不把无法解析的 RF、AF、保持、向量或航向腿画成端点直线。
- 不使用 PDF OCR 构造权威程序；OCR 未来只能用于全文检索。
- 冲突数据保留来源值并进入验证报告，不做平均或无依据修正。

## 时效性

- 所有发布记录必须有带时区的 `valid_from` 和 `valid_to`。
- API 默认只允许 `valid_from <= now < valid_to` 且质量状态为 `verified` 的记录。
- Preview 与历史发布必须显式请求，并在 UI 中醒目标识。
- 新周期校验失败时，旧周期到期后显示“无有效数据”，不能延寿。

## 许可

- 代码许可与数据许可完全分离。
- `review-required` 与 `link-only` 数据禁止进入可再分发发布集。本机研究权限由独立的 local_access 判断，不能通过放宽再分发状态来启用本机数据。
- acquisition 与 processing 分开登记。允许状态必须包含公开证据和核对时间；CIFP 的协议操作与解析证据均未完成，保持阻断。
- NASR 的免费、无需注册下载及 CSV 使用说明，只作为本地获取/研究处理依据。d-TPP 只允许已核实的 XML 目录本地研究，不自动镜像航图 PDF。
- 官方网站可公开访问，不代表文件允许镜像或衍生后再分发。
- 每个发布包必须携带来源、归属、许可证状态、原件哈希和限制。

## 当前证据边界

- d-TPP XML 根属性提供明确的带时刻有效区间；其无坐标机场目录可以独立检索，但不能变成地图机场点。
- NASR EFF_DATE 只有日期，现有资料不足以证明 UTC 生效时刻。自动获取与解析保留原件和报告，不创建猜测有效期的发布。
- CIFP Readme 的09:01 UTC和版本例外只适用于有该证据的CIFP产品。结构读取器不声明引用唯一或分支已验证，其报告保持阻断。
- 程序与航图名称相似不能证明一一对应。没有确定规则时，保留同机场、相容周期的航图目录供选择。

## 几何

IF/TF 引擎只对已唯一核实的点工作。TF 检查紧邻原始腿、分支、原件/成员和源行顺序；其他腿形成缺口。测地线表示名义航段，不包含完整转弯预测。NASR 坐标保留 NAD83 标识，不宣传为测量级 WGS84 坐标。

## 测试资料

合成样本必须在测试目录明确标识，集成测试使用临时数据库，不写入普通 data 目录。真实 FAA 原件和节选保留在本机忽略目录；在再分发依据未确认前不提交 Git。

## 社区数据

OurAirports、OpenAIP 和 OpenFlightMaps 只能作为独立参考层、别名来源或异常发现工具。它们不能静默覆盖 A 级官方数据；经社区源发现的问题必须回到相应 AIS 核实后才能进入默认图层。

## 运行用途边界

本项目不建立适航导航数据库，也不替代 NOTAM、AIP 修订、飞行前简报或管制许可。所有页面和 API 都必须保留非运行用途声明。
